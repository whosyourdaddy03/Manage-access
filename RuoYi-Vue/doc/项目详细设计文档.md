# 项目详细设计文档

## 1. 系统总体设计

### 1.1 系统架构模式
本系统采用 **Browser/Server (B/S)** 三层架构模式：
- **前端展现层**：Vue 2 + Element UI + ECharts，运行于浏览器中
- **后端服务层**：Spring Boot 3.x，提供 RESTful API
- **数据存储层**：MySQL 数据库存储业务数据，本地文件系统存储图片与模型文件

### 1.2 Maven 模块结构
```
ruoyi (父工程)
 ├── ruoyi-admin         # Web 启动模块
 ├── ruoyi-common        # 通用工具类
 ├── ruoyi-framework     # 框架核心（Spring Security、配置）
 ├── ruoyi-system        # 系统管理模块
 ├── ruoyi-generator     # 代码生成器
 ├── ruoyi-quartz        # 定时任务
 └── ruoyi-visualization # 可视化系统（自定义模块）
```

## 3. 后端详细设计

### 3.1 VisiualizationDataController
**路径**: `/visiualization/data`

| 方法 | 路径 | 参数 | 返回 | 说明 |
|------|------|------|------|------|
| GET | /queryRawData | id (String) | AjaxResult | 获取标注 XML 原始数据 |
| GET | /queryPicture | id (String) | 图片流 (JPEG) | 绘制带标注框的图片 |
| GET | /queryPrediction | - | AjaxResult | 查询最新预测结果 |
| GET | /generationModel | - | AjaxResult | 异步启动模型生成（调用 Python） |
| GET | /queryAllEpochIds | - | AjaxResult | 查询所有 epoch 组 ID |
| GET | /queryEpochResults | - | AjaxResult | 查询所有 epoch 结果 |
| GET | /queryEpochResultsByGroup | id (String) | AjaxResult | 按分组查询 epoch 结果 |
| GET | /queryDatasetList | - | AjaxResult | 查询数据集统计列表 |
| GET | /queryImageList | folder, pageNum, pageSize | AjaxResult | 分页查询图片列表 |
| GET | /getRawImage | id (String) | 图片流 (JPEG) | 获取原始图片（不含标注） |

**核心逻辑**:
- `queryPicture`: 从 annotations 表获取标注坐标，读取本地 JPEG 文件，使用 Java AWT `Graphics2D` 绘制红色矩形框后输出
- `queryImageList`: 扫描本地文件系统目录，按文件名排序并分页返回
- `generationModel`: 通过 `ProcessBuilder` 启动 Python 脚本执行模型生成，异步读取输出

### 3.2 TrainingTaskController
**路径**: `/visiualization/training`

| 方法 | 路径 | 参数 | 返回 | 说明 |
|------|------|------|------|------|
| GET | /list | - | AjaxResult | 查询所有训练任务 |
| GET | /detail | id (String) | AjaxResult | 查询任务详情 |
| POST | /sync | - | AjaxResult | 从 epoch 结果表同步任务 ID |
| GET | /epochResults | id (String) | AjaxResult | 按任务查询 epoch 结果 |
| GET | /download | id, type | 文件流 | 下载模型文件 |

**核心逻辑**:
- `syncTaskIds`: 使用 `INSERT IGNORE SELECT DISTINCT` 从 `annotations_epoch_results` 同步任务 ID
- `download`: 根据 type (best/last) 选择对应路径，通过 `FileInputStream` 流式输出

### 3.3 ModelRegistryController
**路径**: `/visiualization/model`

| 方法 | 路径 | 参数 | 返回 | 说明 |
|------|------|------|------|------|
| GET | /list | - | AjaxResult | 模型列表 |
| GET | /detail | id (Long) | AjaxResult | 模型详情 |
| POST | /register | ModelRegistry (JSON) | AjaxResult | 注册模型 |
| PUT | /update | ModelRegistry (JSON) | AjaxResult | 更新模型 |
| DELETE | /delete | id (Long) | AjaxResult | 删除模型 |
| POST | /setInUse | id (Long) | AjaxResult | 切换为使用中 |
| GET | /scanLocal | dirPath (String) | AjaxResult | 扫描本地未注册模型 |

**核心逻辑**:
- `setInUse`: 先 `clearInUseStatus()` 将所有模型置为 archived，再 `setInUseStatus(id)` 将指定模型置为 in_use，保证唯一启用
- `scanLocal`: 使用 `NOT EXISTS` 子查询对比数据库中已注册路径，返回未注册的 .pt 文件

### 3.4 InferenceController
**路径**: `/visiualization/inference`

| 方法 | 路径 | 参数 | 返回 | 说明 |
|------|------|------|------|------|
| POST | /single | file (MultipartFile) | AjaxResult | 单张图片推理 |
| POST | /batch/start | file (MultipartFile) | AjaxResult | 启动批量推理 |
| GET | /batch/status | taskId | AjaxResult | 查询批量推理状态 |
| GET | /batch/list | - | AjaxResult | 批量任务列表 |
| GET | /batch/download | taskId | 文件流 (ZIP) | 下载批量结果 |
| GET | /latest | - | AjaxResult | 最新检测摘要 |

**核心逻辑**:
- `singleInference`: 获取使用中的模型路径 -> 提取 Python 脚本 -> 保存上传图片 -> 调用 Python 进程 -> 解析 JSON -> 读取结果图片转 base64 -> 返回
- `startBatchInference`: 保存 zip -> 解压 -> 创建 BatchTask -> 异步线程执行批量推理 -> 实时更新进度
- Python 输出解析：每行 JSON，单张推理输出 `detections` 数组；批量推理输出 `progress` 类型进度

### 5.3 核心函数

#### run_inference (单张推理)
```python
def run_inference(model_path, input_path, output_path):
    model = YOLO(model_path)
    results = model(input_path, verbose=False)  # 静默模式，不打印日志
    # 绘制检测结果并保存
    for r in results:
        im_array = r.plot()
        cv2.imwrite(output_path, im_array)
    # 提取检测信息
    detections = []
    for box in results[0].boxes:
        detections.append({
            "class": int(box.cls[0].item()),
            "class_name": results[0].names[int(box.cls[0].item())],
            "confidence": round(box.conf[0].item(), 4),
            "bbox": [round(float(x), 2) for x in box.xyxy[0].tolist()]
        })
    # 输出 JSON 到 stdout
    print(json.dumps({"detections": detections, "count": len(detections)}))
```

## 8. 安全方面做了哪些处理

### 8.1 接口权限
可视化相关的 API 接口都加了 `@Anonymous` 注解，所以不登录也能访问（主要是做毕设展示时方便）。框架自带的 Spring Security 过滤器链还是保留的，其他管理接口有 JWT 保护。

### 8.2 调用 Python 时的安全考虑
- 前端限制了上传文件类型，只接受图片和 .zip
- Java 只解析 Python 输出的 JSON 数据，不会执行其他命令
- 每次推理都在独立的 UUID 临时目录里进行，不会跟原始数据混在一起

### 8.3 文件路径处理
- 模型路径是从数据库里读的，不是直接接受用户输入的路径，避免了路径穿越问题
- 图片路径根据 ID 前缀自动映射到对应的文件夹，用户不能随意指定路径

## 9. 性能优化

### 9.1 数据库优化
- epoch 结果表按 id 字段排序，id 建立索引
- annotations 表按 id 前缀分组统计，避免全表扫描
- 批量操作使用 INSERT IGNORE 避免重复数据

### 9.2 前端优化
- ECharts 使用 `setOption(option, true)` 的第二个参数 `true` 表示不合并之前的配置
- 异步加载：Dashboard 同时发起 `queryAllEpochIds` 和 `queryEpochResults`
- 图片懒加载：`el-image` 的 `lazy` 属性

### 9.3 推理优化
- 批量推理使用异步线程池（`Executors.newCachedThreadPool()`）
- Python 脚本使用 `verbose=False` 减少输出开销
- 结果图片 base64 编码直接嵌入响应，减少一次 HTTP 请求

### 11.1 Python 编码问题
```java
// Java 调用 Python 时需设置 UTF-8 编码
pb.environment().put("PYTHONIOENCODING", "utf-8");
pb.redirectErrorStream(true);
```

### 11.2 图片跨域问题
```javascript
// Canvas 绘制图片时需要设置 crossOrigin
img.crossOrigin = 'anonymous'
```

### 11.3 SQL 模式冲突
若遇到 `only_full_group_by` 错误，修改 MySQL 配置：
```sql
SET sql_mode=(SELECT REPLACE(@@sql_mode,'ONLY_FULL_GROUP_BY',''));
```
