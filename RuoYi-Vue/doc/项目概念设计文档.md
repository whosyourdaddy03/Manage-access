# AI训练检测平台 - 概念设计文档

## 1. 项目概述

### 1.1 项目背景
本项目是基于 **RuoYi-Vue** 框架二次开发的 YOLOv8 目标检测训练可视化管理系统，同时也是我的本科毕业设计课题。在做毕设的过程中，我发现训练 YOLOv8 模型时存在几个挺让人头疼的问题：

- 训练过程中的 Loss、mAP 这些指标只能看控制台输出，没有一个直观的图表界面
- 训练产出的 .pt 模型文件散落在各个文件夹里，时间长了根本分不清哪个是哪个
- 想用训练好的模型做推理测试，还得自己写脚本或者用命令行

所以我就想能不能做一个 Web 平台，把这些事情都整合到一起，从数据标注的查看、训练过程的监控，到模型的管理和在线推理，一条龙搞定。

### 1.2 毕业设计目标
- **训练可视化**：把 YOLOv8 训练时每轮的 Loss、mAP、Precision/Recall、Learning Rate 等指标用 ECharts 图表展示出来
- **数据资产管理**：能浏览数据集里的图片，查看标注框画得怎么样
- **训练任务管理**：记录每次训练的参数配置，能下载训练好的模型文件
- **模型注册中心**：统一管理所有训练产出的 .pt 模型，支持对比和切换启用
- **在线推理服务**：上传图片就能调用模型做检测，支持单张和批量两种模式

### 1.3 系统定位
这个系统主要面向像我一样做目标检测相关学习和研究的学生或开发者，帮助大家更直观地了解模型训练效果，减少在模型管理和推理部署上的重复劳动。

## 3. 功能模块设计

### 3.1 功能模块划分

```
AI训练检测平台
├── 1. 首页仪表盘 (Dashboard)
│   ├── 统计卡片 (8个关键指标数值)
│   ├── 训练ID选择器 (按训练任务筛选)
│   └── ECharts趋势图 (4个)
│       ├── Loss变化趋势
│       ├── mAP变化趋势
│       ├── Precision/Recall变化趋势
│       └── Learning Rate变化趋势
│
├── 2. 数据资产管理
│   ├── 数据集列表 (按文件夹分组统计)
│   ├── 图片浏览 (分页缩略图)
│   └── 标注可视化 (Canvas绘制标注框)
│
├── 3. 训练任务管理
│   ├── 任务列表 (历史训练记录)
│   ├── 任务详情 (训练曲线 + 模型下载)
│   └── 一键同步 (从epoch结果自动创建任务)
│
├── 4. 模型管理中心
│   ├── 模型注册 (手动填写/自动扫描)
│   ├── 模型编辑与删除
│   ├── 启用/归档切换
│   └── 模型对比 (柱状图展示指标)
│
└── 5. 在线推理服务
    ├── 单张推理 (上传 → 检测 → 结果展示)
    └── 批量推理 (ZIP上传 → 异步处理 → ZIP下载)
```

### 3.2 各模块详细说明

#### 3.2.1 首页仪表盘 (Dashboard)
- **定位**：系统首页，一打开就能看到最新的训练效果
- **核心功能**：
  - 8个统计卡片：总训练轮次、数据集数量、最新的 mAP50、mAP50-95、Precision、Recall、Train Loss、Val Loss
  - 训练ID选择器：用 `el-select` 下拉选择，切换时图表数据跟着变
  - 4个 ECharts 折线图：Loss、mAP、Precision/Recall、Learning Rate 的变化趋势
- **数据来源**：`annotations_epoch_results` 表，默认加载最新的训练任务数据

#### 3.2.2 数据资产管理
- **定位**：浏览和管理训练数据集
- **核心功能**：
  - 数据集列表：按图片 ID 前缀（如"01"、"02"）分组统计
  - 图片浏览：分页展示缩略图，支持按 ID 搜索
  - 标注可视化：用 Canvas 在原图上绘制红色 GT 框，支持滚轮缩放和拖拽平移
- **技术要点**：标注框用 Java AWT `Graphics2D` 在服务端绘制后返回图片流

#### 3.2.3 训练任务管理
- **定位**：查看和管理历史训练任务
- **核心功能**：
  - 任务列表：展示所有训练任务（ID、时间、模型版本、Epochs、Batch Size 等）
  - 任务详情：跟首页差不多，也是 4 个训练曲线图，外加模型文件下载
  - 一键同步：从 epoch 结果表里提取不重复的任务 ID 自动创建任务记录
- **数据来源**：`annotations_training_tasks` 表（元数据）+ `annotations_epoch_results` 表（指标）

#### 3.2.4 模型管理中心
- **定位**：统一管理训练产出的模型文件
- **核心功能**：
  - 模型注册：手动填写模型信息，或者扫描本地目录自动发现未注册的 .pt 文件
  - 编辑/删除：修改模型元数据
  - 设为使用中：同一时间只能有一个模型是 "in_use" 状态，切换时自动归档其他模型
  - 版本对比：用 ECharts 柱状图对比多个模型的 mAP 和推理速度
- **数据来源**：`model_registry` 表

#### 3.2.5 在线推理服务
- **定位**：快速验证模型效果
- **核心功能**：
  - 单张推理：上传图片 → 后端调 Python 脚本 → 返回带检测框的结果图和检测数据
  - 批量推理：上传 ZIP 包 → 后台异步逐张处理 → 前端轮询进度 → 完成打包下载
- **技术实现**：Java 通过 `ProcessBuilder` 调用 Python 进程，用 JSON 格式传数据

## 4. 业务流程设计

### 4.1 数据导入流程
```
YOLOv8训练完成 → 生成results.csv → 解析写入annotations_epoch_results表
  → 从epoch结果提取唯一ID → 同步到annotations_training_tasks表
  → 首页自动加载最新训练数据 → 展示图表和统计指标
```

### 4.2 模型注册流程

**手动注册**：填写模型信息 → 提交到 model_registry 表 → 可选设为使用中

**自动扫描**：点击"扫描本地" → 遍历指定目录的 .pt 文件 → 对比数据库已注册路径 → 列出未注册的 → 一键批量注册

### 4.3 在线推理流程

**单张推理**：
```
1. 前端上传图片 → 后端保存到临时目录
2. 调用 Python: inference.py --mode single --image input.jpg --model best.pt
3. YOLOv8 推理 → 绘制检测框 → 保存结果图
4. Python 输出 JSON 格式检测结果到 stdout
5. 后端解析 JSON → 结果图片转 base64 → 返回给前端
6. 前端显示检测结果图和检测框列表
```

**批量推理**：
```
1. 前端上传 ZIP → 后端解压
2. 异步线程逐张调用 Python 推理
3. 每处理一张就输出进度 JSON → 后端更新任务状态
4. 前端每 2 秒轮询进度 → 进度条实时更新
5. 全部完成 → 打包结果 → ZIP 下载
```

## 5. 数据流设计

### 5.1 数据表关系
```
annotations (标注数据)
    ↓ (按ID前缀分组统计)
数据集列表 (前端展示)

annotations_epoch_results (训练指标)
    ↓ (DISTINCT id)
annotations_training_tasks (训练任务)
    ↓ (training_task_id 关联)
model_registry (模型注册)
    ↓ (推理时选择 in_use 模型)
Python推理引擎 → 前端展示检测结果
```

### 5.2 核心数据流
- **标注数据流**：`annotations` 表 → `VisiualizationDataController` → Canvas 绘制标注框
- **训练指标流**：`annotations_epoch_results` 表 → ECharts 折线图展示
- **模型元数据流**：`annotations_training_tasks` + `model_registry` → 前端列表和对比图表
- **推理数据流**：用户上传 → `InferenceService` → Python 进程 → JSON 结果 → 前端展示

## 6. 前端界面设计思路

### 6.1 设计风格
系统的主色调沿用了 Element UI 默认的蓝色系，侧边栏用了 RuoYi 框架原生的深蓝灰背景（#304156）。整体风格偏简洁实用，没有搞太花哨的设计，毕竟主要目的是功能好用。

Logo 换了一个自定义的 SVG 图标（AI 芯片造型），主要是想让页面看起来不像原生的 RuoYi 后台管理系统，有点自己的特色。

### 6.2 交互设计上的一些考虑

- **统计卡片**：加了 hover 上移 + 阴影效果，虽然没啥实际功能，但视觉反馈会让页面感觉更"活"一点
- **图片网格**：缩略图悬浮时也有阴影效果，方便知道鼠标当前 hover 到哪张图了
- **Canvas 标注**：支持滚轮缩放和拖拽平移，这个做的时候花了不少功夫，主要是想方便查看标注细节
- **批量推理进度**：用 `setInterval` 每 2 秒轮询后端进度，虽然不如 WebSocket 实时，但实现简单，对毕设来说够用了
- **表单校验**：用了 Element UI 自带的 `el-form rules`，确保必填项不会漏填

### 6.3 布局适配
统计卡片和图表区域用了 Element UI 的 24 栅格系统，大屏上图表可以并排两列显示，小屏就自动堆叠成单列。不过说实话，移动端适配只是简单做了一下，主要还是以桌面端为主。

### 6.4 踩过的一些坑

- **Canvas 跨域问题**：直接从后端加载图片绘制到 Canvas 时遇到了跨域问题，需要在 `img` 标签上设置 `crossOrigin = 'anonymous'`
- **ECharts 数据排序**：后端返回的 epoch 数据不一定是按顺序的，前端需要自己 `sort((a, b) => a.epoch - b.epoch)` 排一下
- **Python 编码问题**：Java 调用 Python 进程时，如果不设置 `PYTHONIOENCODING=utf-8`，中文路径会乱码

## 7. 安全性考虑

### 7.1 认证机制
沿用了 RuoYi 框架自带的 JWT Token 登录认证。可视化相关的 API 接口加了 `@Anonymous` 注解，这样未登录也能访问（主要是为了方便演示）。

### 7.2 常规防护
- **SQL 注入**：全部用 MyBatis 参数绑定 `#{}`，没有拼接 SQL
- **XSS 防护**：框架自带的 XSS 过滤器会对用户输入做转义
- **文件上传限制**：只允许上传 .jpg、.png 和 .zip，限制了文件大小

### 7.3 Python 进程安全
- 所有推理文件放在独立的临时目录，不会污染原始数据
- 只解析 Python 输出的 JSON 数据，不会执行其他命令
- 批量推理限制了最多 100 张图片，防止资源耗尽

## 8. 可扩展性

### 8.1 模块化设计
`ruoyi-visualization` 是一个独立的 Maven 模块，跟 RuoYi 框架的主业务逻辑解耦。如果想加新功能，只需要在这个模块里加 Controller/Service/Mapper 就行。

### 8.2 可能的扩展方向
- **多模型支持**：当前只接了 YOLOv8，抽象一下接口可以支持 YOLOv5、YOLOv10 等
- **更多数据集格式**：当前标注数据是 VOC 格式，可以扩展 COCO、YOLO 格式
- **实时训练监控**：现在是离线导入 CSV 数据，理论上可以改成 WebSocket 实时推送

## 10. 后续想做的事情

### 10.1 短期内想优化的
- 训练任务的手动创建和编辑功能，目前只能从 epoch 结果同步，不太灵活
- 批量推理的进度用 WebSocket 推送，现在 2 秒轮询有点 low
- 模型导出 ONNX 格式，方便在不同平台部署
- 推理结果加个导出 CSV/JSON 的功能

### 10.2 如果时间充裕的话
- 多用户支持，现在只能一个人用，团队协作不太行
- 训练任务对比模式，把两个训练任务的曲线叠在同张图表上对比
- 数据集管理再丰富一点，支持上传、删除、标注统计之类的

### 10.3 当时做毕设的一些遗憾

说实话，做这个毕设最大的遗憾是时间不够（而且中间还踩了不少坑），很多想法没能完全实现：

- 最开始想做成实时监控训练进度的，但发现要改 YOLOv8 训练脚本的日志系统，工程量有点大，最后改成了离线导入 CSV
- Canvas 标注可视化那一块花了远超预期的时间，缩放和拖拽的细节调试了很久
- 界面适配只做到能用的程度，跟专业的前端项目比还有很多粗糙的地方

不过总的来说，这个系统把训练可视化管理这个流程基本走通了，该有的功能都有了，对自己来说也算是一次比较完整的全栈开发实践吧。

## 附录

### A. 术语表

| 术语 | 英文全称 | 说明 |
|------|----------|------|
| mAP | mean Average Precision | 平均精度均值，目标检测核心指标 |
| IoU | Intersection over Union | 交并比，衡量预测框和真实框的重合度 |
| Epoch | - | 一个 epoch = 遍历完整个训练集一次 |
| Batch Size | - | 每批次处理的样本数量 |
| Loss | - | 损失函数值，衡量模型预测和真实值的差距 |
| Precision | - | 精确率，预测为正样本中实际为正的比例 |
| Recall | - | 召回率，实际正样本中被正确预测的比例 |
| YOLO | You Only Look Once | 实时目标检测算法，目前到 v8 版本 |
